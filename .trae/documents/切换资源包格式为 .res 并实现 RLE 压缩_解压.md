## 目标
- 新增 NodeJS `en.js`：为指定目录下同级子目录分别打包成 `.res` 文件（文件名=子目录名）。
- 改造 `res.js/res.ts`：`url()` 加载 `.res`；解析头部 JSON；按定制 RLE（分片重复与间隔重复）解压；替换现有下载/加载逻辑。

## `.res` 格式
- Header：`magic(RES1/4B)` + `headerLen(uint32 LE)` + `headerJson(UTF-8)`；`headerJson` 包含 `files`（name/mime/size/offset/compSize）与 `groups`（分组到文件列表映射）。
- Body：按 `files` 顺序写入各文件的压缩流（由块拼接）。

## RLE 块规范（精确）
- RAW：`0x00` + `len_u16` + 原始 `len` 字节
- 分片重复：`[seq_len_u8(0x01..0x50)] [run_u8] [seq_bytes...]`
  - 解包：输出 `seq_bytes` × `run_u8`（无额外 code，`seq_len` 即 code）
- 间隔重复：`[opcode(0x51..0x62)] [repeat_byte_u8] [repeat_total_u8] [tail_bytes...]`
  - `stride = opcode - 0x50`（1..18）
  - `repeat_total_u8 = 组数-1`；`tail_len = (stride-1)*(repeat_total+1)`（不存长度）
  - 解包：将 `tail_bytes` 划分为 `repeat_total+1` 组（每组 `stride-1`），每组前插入 `repeat_byte` 后拼接输出。

## 压缩收益分析（选择策略）
- 间隔重复块：
  - 压缩长度：`3 + (stride-1) * G`（3=opcode+repeat_byte+repeat_total，G=组数）
  - 原始长度：`stride * G`
  - 收益条件：`3 + (stride-1) * G < stride * G` ⇔ `G > 3`
  - 选择策略：仅当 `组数 > 3` 时采用间隔重复，否则回退 RAW/分片重复。
- 分片重复块：
  - 压缩长度：`2 + seq_len`（2=seq_len+run，写入一次序列）
  - 原始长度：`run * seq_len`
  - 收益条件：`2 + seq_len < run * seq_len` ⇔ `2 < (run - 1) * seq_len`
  - 选择策略：仅当上述条件满足时采用分片重复，否则回退 RAW。
- RAW：作为兜底，合并连续 RAW 块以减少块数量。

## `en.js` 实现
- 遍历子目录；收集文件；生成 Header；写 Body：
  - 逐字节扫描：
    - 优先评估分片重复（枚举 `seq_len≤0x50` 与 `run`），满足收益条件则输出分片块。
    - 再评估间隔重复（枚举 `stride=1..18` 检测恒定首位），满足 `G>3` 则输出间隔块（`opcode/repeat_byte/repeat_total/tail_bytes`）。
    - 其余输出 RAW 并合并相邻 RAW。
- 输出压缩报表：分块统计与收益判断。

## `res.js/res.ts` 改造
- `url(resPath)`：加载 `.res`，解析头部与包 Blob；归一化 `groups` 到 `Res._list`。
- 解压器：顺序解析块：RAW/分片重复/间隔重复（按公式推导 `tail_len`，准确恢复）。
- `down(key)`：依据 `groups[key]` 与 `files` 索引，将包内对应文件解压为 Blob 填充 `Res._img[key][subKey][index]`；维护进度与事件。
- `load/loadTexture`：以 `createObjectURL` 交付 Blob 给 `Laya.loader`（保持 atlas/spine 分支工作流）。
- 兼容：`url()` 同时支持旧 `.json` 与新 `.res`。
